# 设计草案：武器常驻特效

目标：在 native 与 WebGPU 的同一个预览器里，播放武器当前变体真实挂载的常驻效果。验收样本为屠龙戟·灵光（16053）和圣母盾·灵光（16063）。范围由两件样本实际依赖的节点、材质与挂点决定；不以“能读 AVFX”宣称完整播放支持。

## 资产契约

- 宿主在准备资源时，对每个武器部件解析 IMC 的 subset/part 和 `vfx_id`。确认无挂载和未解析分别记录；副手复用主手 IMC 时仍保留实际效果所属部件。
- 在已有物品清单的 `parts[]` 上增加可选 `effects[]`，每项给出 AVFX 逻辑路径、挂点描述及依赖路径。纹理（ATEX）和需要的骨架（SKLB）继续用现有 `files` 路径到摘要映射，不复制共享对象。AVFX 自带的效果网格由 AVFX 解码，不假设它是另一个装备 MDL。
- DB 负责解析 URL、校验摘要、下载和缓存字节。renderer 只收描述及资源字节；不依赖物品 ID、SqPack、本地路径或 TOS。旧清单及无挂载武器继续走静态路径。

## 播放与绘制

1. **先建立可复查的效果输入。** 用 `icexiv-data::avfx` / `tex` 读取资源，从两个样本导出依赖、节点类型与绑定记录。把 companion 的时间线、发射、随机和绑定求值与其 UI、资源加载分开；优先移植两个样本覆盖且有基准的纯计算，再以相同输入核对每帧输出。不再实现一套二进制解析器。
2. **保留坐标变换。** 当前 `EquipmentModel::from_mdl` 用 `(p - center) / radius` 直接改写顶点。需保留模型原空间到预览空间的变换，以及挂点需要的原始几何或绑定姿势。粒子在效果/武器空间求值，最终与武器共享变换、相机和深度。不要把绑定 ID 当骨骼数组下标，也不要靠逐物品手调偏移。
3. **分开模拟与绘制。** 提议 `EffectPlayer` 持有种子、时钟和粒子历史；`advance(dt, pose)` 使用固定步长，`reset(seed)` 允许确定性回放。绘制本身不推进时间。武器先写深度，常见透明或加法粒子读取同一深度、按效果混合与排序；表面 Aura 需要宿主网格，不能一律替换成面向相机的亮片。未支持节点返回带路径和节点类型的诊断；仍绘制模型及可用效果。
4. **由 Web Component 管理播放。** 提议 SDK 增加装载/清空效果、推进和重置接口，native/Web 共用 Rust 实现。组件仅在效果开启且可见时连续请求帧；隐藏时暂停，恢复时不追赶后台时间。更换部件取消旧下载并清空旧实例，关闭时释放 GPU 资源。固定每次补步、存活粒子及贴图预算；达到限制要可诊断。

## 验收和实施顺序

先在 renderer 的 native 示例中用真实字节跑通 16053，再接 Web Component，最后接 DB 全库依赖扫描。16063 作为表面 Aura 的独立验收，不用枪的火焰代替盾的效果。

- 对同一模型、相机、种子与姿态，记录关闭特效、连续从零推进到 0.8 秒和 4 秒的真实画面；与 companion 相同输入下的挂载位置、轮廓和时间变化对照。只与静态基线像素不同，不足以通过。盾例沿用网页的 Aura 选择，不直接跳到目标时刻。
- 浏览器验证启停、重播、相机绕转、缩放和切换部件；无 VFX 时不下载附加文件、不开持续帧循环；丢失贴图或不支持节点时静态预览仍可用。
- 在全库报告中单列无挂载、资源未解析、部分播放及已验证播放；不并入静态模型材质槽通过数。武器常驻挂载通过不代表技能触发、战斗场景或游戏像素完全一致。
